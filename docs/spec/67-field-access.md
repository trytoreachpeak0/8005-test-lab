# Field access：现场的人怎么够着 lab

Courier（`65-courier.md`）与 Vigil（`66-vigil.md`）是 **lab → 人**，本文是**人 → lab**，同一族的
反方向。三者互不共用通路：前两条都是单向出去的。

**接触面只有一个：探针的 `workRoot` 根**（`10-registry-and-binding.md` 里每台机器声明的那个目录）。
本文不新增任何通路，只定那个目录里的文件约定。现场的人要学会的只有一件事——**在这个目录里放文件**。

## 1. `workRoot` 根下与人有关的四样

| 文件 | 谁写 | 谁读 | 存在意味着 |
| --- | --- | --- | --- |
| `HALT*` | 人 | 探针 | 立刻降只读（`70-judgement.md` / #15，语义不变） |
| `field-authorization.pending.json` | 探针 | 人 | 「我被额度挡下了一个动作，等你批」 |
| `field-authorization.json` | 人 | 探针 | 「我批了这一个动作」 |
| `field-authorization.accepted.json` | 探针 | 人 / 下一次的自己 | 「我在某时刻收下了哪一份凭证」 |

**人填的那份凭证 lab 只读不改**：不改名、不加标记。探针要记的写进它自己那份 `accepted`。

## 2. 叫停：判据宽、路子多，因为它的失败方向是「该停没停」

授权与叫停的失败方向相反，所以两者判据分开：授权要**难**，叫停要**可达**。

**判据**：`workRoot` 根下**任何以 `HALT` 开头的条目**——大小写不敏感，文件或目录都算，
**内容一律不解析**。

放宽的是判据不是语义。它挡住的是这三种「他以为叫停了而实际没有」：

- 记事本另存为默认追加 `.txt` → `HALT.txt`
- 资源管理器隐藏已知扩展名 → 人看见 `HALT`、真名 `HALT.txt.txt`
- 大小写 → `halt`

**不做桌面快捷方式。** 它更快更不易错，但它正好命中地图那条判据——「给人一个可以点的地方才是
界面」。易用性买在判据的宽容度上，不买在界面上。

**投放路径三条，全部保留，不做二选一**：

| # | 路 | 依赖 |
| --- | --- | --- |
| 1 | 车上触控屏（已自动登录的桌面） | 只依赖人能走到车边。**唯一不依赖任何网络的一条，是兜底** |
| 2 | VNC | 人在厂内网上 |
| 3 | 控制端 ssh | 控制端活着且连得上——失明期间可能正是这条断了 |

**第 2 条不是本规格的一部分。** 本规格定的是「`workRoot` 里的一个文件」；人用什么方式到达那台
机器不在范围内。这条区分是刻意的：现场今天那条 VNC 路依赖一个空密码账户，把它写进规格等于把
授权链建在那上面，并给了「别修它」一个理由。修了它第 2 条就没了，第 1 条还在。

**`HALT` 压倒一切**：探针每轮第一件事是检查它，早于任何采集，所以 `HALT` 在时探针走不到读凭证
那一步。叫停永远压倒授权。

**恢复不变**：删文件不恢复，只能靠 `lab watch grant`（要求控制端连得上探针）。

## 3. `HALT` 不是车的急停

**接入文档与现场卡片的第一行，不能排在第二行：**

> **放 `HALT` 只让 lab 停手。要让车停下来，用车上的急停。**

`HALT` 让探针降只读、不再执行任何修复。**它不会让一台正在走的车停下来。** 车辆本体的紧急停止是
另一套东西（RIoT 车辆状态里的 `emergencyState`，动车前的只读复核读的就是它），属 RC 第 11 节的
硬件部分，在地图 Out of scope。

**卡片落地前必须由知道现场的人把上面那句的后半句填成一个具体动作**——按钮在车的哪一面、什么
颜色、按下之后要不要复位。一张写着「用车上的急停」而没说清是哪个的卡片，与没有卡片差别很小。

## 4. 现场授权：草稿由探针写，且只在真的挡下一个动作时才写

适用条件：`tier: production` 上安全门判出 `deniedByGrant`（`physical` 额度不足）。

1. **探针写 `field-authorization.pending.json`**，填好它知道的一切：`pendingId`、`watchId`、机器名、
   动词与参数、触发它的 `invariantId`、`stateBefore` 快照的 sha256，以及**一句人话说明这个动作会
   让车做什么**（载荷与 Courier 同源，是 `ledger.md` 那一段的原文）。
2. **人填三样**，另存为 `field-authorization.json`：

   | 字段 | 内容 |
   | --- | --- |
   | `grantedBy` | 真人姓名，不是账户名 |
   | `decidedAt` | 人给的时刻。**只进账，不参与任何判定**（见第 6 节） |
   | `statement` | 他此刻在车边看到了什么。除 `minLength: 1` 外不校验 |

3. **探针下一轮捡起**，校验通过即把**这一个动作**的额度提到 `physical`，执行，写账。

**没有待批动作就没有草稿。** 人无法预先给出授权，所以 RC 第 11 节「逐次授权、每次都要、不可复用」
是**结构性的**，不是一条要靠人记住的纪律。

**额度是 1**，不是 `70-judgement.md` 里 `physical` 那个默认 3。那个 3 是给控制端下发的长凭证定的
（Watch 的修复不可预期，次数上限是唯一说得通的收敛）；现场凭证绑定在一个已经具体化的待批动作上,
**它已经是逐次的了**。生产装置上 `physical` 的次数上限因此结构性地是 1。

**不经 CLI，不新增子命令。** 现场授权的整个意义就是不需要控制端。

## 5. 绑定：三样，任一对不上即拒绝

| 绑定 | `reasonCode` | 挡住什么 |
| --- | --- | --- |
| `pendingId` 对得上草稿 | `fieldAuthorizationNotBound` | 凭证被拿去批另一个动作 |
| `stateSnapshotSha256` 对得上 | `fieldAuthorizationNotBound` | 现场状况在人签字之后变了 |
| 凭证自身的 sha256 不在 `accepted` 里 | `fieldAuthorizationConsumed` | 同一份凭证用第二次 |
| 三个字段齐全且可解析 | `fieldAuthorizationMalformed` | 填漏了、存坏了 |

三个 `reasonCode` 都是 `layer: kernel`、`definedBy: "#27"`。

## 6. 到期只用相对时长——本规格对两个钟的明确例外

`70-judgement.md` 的 Grant 到期用两个钟取先到者。**现场凭证只用相对时长**：

- **绝对时刻这一侧没有可信输入。** `decidedAt` 是人手填的，而车上的时钟是镜像自带的故障（三台车
  上线时都快 158 天，每台必修）。拿它判到期等于把额度寿命交给一个已知会错的钟。
- **15 分钟从探针读到凭证那一刻起算**（单调时钟），上限不可覆盖。
- **「探针重建即归零」照堵**：收下凭证时立刻写 `field-authorization.accepted.json`
  （凭证 sha256 + 收下时刻），重建后先读回；同一份凭证已在里面就不重新起算。

## 7. 留痕：两处

两端在不同机器上，而其中一端按定义可能是死的。

- **探针侧**：捡起 `HALT` 或凭证时把「读到了什么、什么时候、判成什么」写进本地账，随分片回传。
- **控制端侧**：回传后进 `repairs.jsonl` 与 `ledger.md`。账里**必须包含被现场放行的判定，以及放行
  它的那个人**（与 `70-judgement.md` 那条「必须包含被拒绝的判定」对称）。

**`repairs.jsonl` / `gate-decisions.jsonl` 那套共用字段新增三样**：

| 字段 | 值 |
| --- | --- |
| `grantSource` | `watchStart \| fieldAuthorization` |
| `grantedBy` | 原样 |
| `authorizationStatement` | 原样，不截断不改写 |

名字与那句话必须原样进账：**一条只写着「授权已给出」的账，事后没有任何人可以否认它。**

## 8. 送达：新增第 11 类

**第 11 类：人工叫停被读到**（`HALT` 出现，探针降只读）。**即时档**，去重身份的对象是**机器名**
（与第 2 / 3 / 4 类同族），`65-courier.md` 第 4 节那张表加一行。

**不并进第 4 类**（额度过期降只读）：Courier 的围栏是「同一身份的新事件取代还没发出去的旧事件」，
共用身份就会互相围栏掉，而两者的差别恰恰是「有没有人来过」——那正是群里其他人最该知道的一件事。

**现场授权被消费不新增类别**：后面必然跟一次 `physical` 修复，第 1 类已覆盖，账上靠 `grantSource`
分得清。

## 9. 这道门防不住 agent，接入文档必须写死这一句

agent 能自己写 `field-authorization.json`：它有到车的 ssh，凭证没有签名字段，草稿是它自己那个探针
写的。**技术上拦不住。**

严格性等级取自 `8005-agv-protocol` 的 release approval attestation（无签名字段，靠「凭证外部于
仓库、绑定在被批准物的哈希上、记下一个真人的名字与时刻」）。**不发明更高的一档**：RC 11.1 已经
关掉这条路——「正确的做法是先解决网络隔离，而不是在本版本上叠加补偿措施」。

那一档买到三件事，一件都不是「拦住」：

1. 伪造要写下一个真人的名字和一句话——那是**可核、可否认、可追责**的假记录，不是沉默的自我放行。
2. **攒不出可复用的授权**（绑定在草稿 ID 加快照哈希上）。
3. 它不是唯一一道防线：被测系统自己那道安全闸门、15 分钟 TTL、结构性的次数 1、以及必须声明的
   前置条件（`physical` 动词不声明前置条件内核直接拒绝）。

**接入文档写死，与 `65-courier.md` 第 7 节「通道已收 ≠ 人知道了」并列：**

> **`field-authorization.json` 证明的不是「一个人批准了」，是「有人以某个名字在某个时刻说了某句
> 话」。它拦不住 lab 自己造一份。它买到的是：造了就留下一条指着真人的假记录。**

## 10. 落点

- **判定在 `Lab.Judge`**（纯函数：给定凭证、草稿、快照哈希、已消费清单 → 通过或一个
  `reasonCode`），**文件读写在 `Lab.Probe`**。控制端侧零新增：这条通路整个不经过控制端。
- 三个 `reasonCode` 进 `src/Lab.Judge/reason-codes.json`。
- **`lab machine sweep` 具名排除两样**：`HALT*`（`45-footprint.md` 已有）与
  `field-authorization.accepted.json`。**后者的理由不同**——扫掉 `HALT` 只是让人看不出有人来过，
  扫掉 `accepted` 会让一份**已消费的 15 分钟额度复活**。排除是一条带理由的项。
- **草稿的生命周期**：同一个待批动作只写一份；动作不再需要执行时探针删掉它。删草稿不过门——
  它是 lab 自己的东西、`sideEffect: none`。
- **不进登记册，不是角色，不占 `tags`。**

## 11. 这条通路改了「生产装置上一定是 denied」那句话的一半

`70-judgement.md` 那句「destination 第 3 条在生产装置上的 `decision` 会是 `deniedBySafetyGate` 而
不是 `executed`」，**本规格之后只在「没有人在场」时成立**。有人站在车边并填了凭证时是可以走到
`executed` 的——那正是那条收窄规则存在的意义。

**destination 第 3 条不改**：它写的是「生产装置上的差异只有安全门的判定结果」，而「判定结果不同」
既覆盖 denied 也覆盖 executed。
