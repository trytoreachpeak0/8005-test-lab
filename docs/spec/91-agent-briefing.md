# 给 agent 的工作说明

这份规格定的是「怎么把 lab 讲给一个新会话」：几份文档各写什么、按什么顺序到达一个会话手上，
以及一个新会话怎么问出「这台车现在有没有人在看着」。

命令与参数不在这里，也不在任何一份文档里 —— `lab help --json` 现场派生（#33）。

## 1. 前提更正：`CLAUDE.md` 不是「会话开头一定被读到」的那一份

实测 2026-09-09，依据是 Claude Code 自己的加载规则：

- 启动时加载的是 **cwd 及其每一层祖先目录**的 `CLAUDE.md` / `CLAUDE.local.md`；
- **cwd 之下子目录里的那些不在启动时加载**，只在 agent 读到那个子目录的文件时才被带进来；
- 经 `--add-dir` 加进来的目录，缺省一份都不加载。

这张图的会话历来在工作区根启动 —— 八份开工 prompt 所在的 scratchpad 目录名
`C--Users-szy-Desktop-8005-workspace` 就是那个 cwd 的编码。`repos/8005-test-lab/` 是它的子目录，
所以 **lab 的 `CLAUDE.md` 从来没有在会话开头到达过**：它到达的时刻是「会话已经读了 lab 仓的某个
文件之后」，晚于它该起作用的时刻。

三条后果：

1. **预算不紧的正是 lab 这份**（工具方建议每份 200 行以内；筛法
   `wc -l CLAUDE.md repos/*/CLAUDE.md`，2026-09-09 测得 lab 65 行、工作区根 726 行、七份合计
   1781 行）。**紧的是工作区根那份，不是 lab 这份** —— 所以这张票要答的不是「怎么从 `CLAUDE.md`
   里砍东西」。这三个数会长，用那条筛法现数，别引这里。
2. **不能把「它一定会被读到」当成任何一条规则的前提。** 一条「必须在开工前知道」的规则，只写进
   lab 的 `CLAUDE.md` 不足以让它被知道。
3. **让它在会话开头到达的唯一一条路已经走了**：2026-09-09 由用户显式授权，在工作区根 `CLAUDE.md`
   里加了一行裸的 `@repos/8005-test-lab/CLAUDE.md`（import 在启动时展开；写在反引号或代码块里
   不生效）。那份文件**不在写权限表里**（表按 remote 列，`8005-workspace` 不在其中），所以那是
   一次一次性的显式授权，不是本仓可以自己做的事。

   **它只修好了常见的那一种，第 2 条因此不撤销**：从工作区根启动的会话现在开头就拿到这份文件；
   而在本仓内启动的、用 `--add-dir` 带进来的、或者从一个独立 clone 工作的会话仍然拿不到 ——
   `--add-dir` 的目录缺省不加载任何 `CLAUDE.md`（要 `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1`）。
   **一条规则的失败模式如果是「agent 从来没看见它」，它就不该只写在这里。**

## 2. 六份文档的分工，判据是「这段话写错了会怎么坏」

正文那张表是四份，实际是六份 —— `CONTEXT.md` 与本票新增的 `docs/agent-notes.md` 原本没在表上。

| 文档 | 读者 | 什么时候到达 | 装什么 |
| --- | --- | --- | --- |
| `CLAUDE.md` | agent | 读到 lab 仓文件时（**不是会话开头**，见第 1 节） | 一直成立、且写错了会让 agent 直接做错事的规则 |
| `README.md` | 人 | 第一次接触这个仓库 | 这仓库是什么、为什么现在没有代码 |
| `CONTEXT.md` | agent 与人 | 由 `CLAUDE.md` 的一行指针引入 | 只有词的定义 |
| `docs/spec/` | 实现者 | 要改内核或适配层时 | 结论，不重述推理 |
| `docs/agent-notes.md` | agent | 开工前 | 这张图已经踩过的坑（第 9 节） |
| `adapters/<name>/docs/onboarding.md` | 想把另一套系统接进来的人 | 接入时 | #4 定的六节 |

**一段文字进哪一份，看它坏掉时是什么形状：**

- 写错了会让 agent 当场做错事，而没有别的东西会拦它 → `CLAUDE.md`。
- 是一个词的定义，两个人用同一个词指不同的东西会**静默分叉** → `CONTEXT.md`。
- 是「做什么」的结论，下一环照着它写代码 → `docs/spec/`。
- 是「这个坑我们已经踩过」的记录，它不指导任何一次具体实现，但能省掉一次重复的调研 →
  `docs/agent-notes.md`。
- **是命令名、参数、退出码、结局取值 → 哪一份都不写。** `lab help --json` 现场派生（#33）。一份
  写在文档里的命令表就是那份「总有人忘记更新的手写清单」，而它腐烂时没有声音。

## 3. 一个新会话按什么顺序读

```
工作区根 CLAUDE.md（写权限表、PowerShell 7 铁律）
  → lab 的 CLAUDE.md（规则 + 去哪儿找）
  → docs/agent-notes.md（这张图踩过的坑；开工前，不是遇到问题时）
  → lab help --json（有哪些命令、参数长什么样、结局有哪些值、退出码怎么读）
  → docs/spec/（要改内核或适配层才读；索引是 docs/spec/README.md 的分片表）
```

**票不在这条链上。** 票是决策档案不是操作手册，而且今天已经三十六张（2026-09-09 实测：已关闭 25 +
开着 11）。正文说「找到相关的票」这一步是错的 —— 错的不是「读票」，是**检索方式**：在三十六张里
找相关的那张，是一次每个会话都要重做的调研。

**唯一合法的读票方式是跟着一个具名指针走**：某份规格文件说「本条定于 #17」，就去读 #17。
桩文件（第 4 节）与 `docs/spec/README.md` 的分片表都是这种指针。

## 4. 过渡期：`#35` 完成之前，桩文件里的具名指针是链上的一环

`docs/spec/` 十七份里七份仍是 469–495 B 的桩（`10`/`20`/`30`/`40`/`50`/`60`/`70`，2026-09-09 实测），
桩文件正文明写「**在那之前，票的决议评论是权威**（含它们后来的修正评论 —— 那些票的正文与决议一律
不回改，更正以追加评论的形式存在，所以要读到最后一条）」。

这与第 3 节不冲突，**因为桩文件给的是具名指针不是检索任务**：它点名了是哪张票。过渡期的规则是

> 读到一份桩文件，就按它点的票号去读那张票，**并读到最后一条评论**。不要因为看见桩就去票列表里
> 自己找。

#35 每回填一份，链上就少一次跳转。**桩文件消失的那天这一节自动失效**，不需要谁记得删它。

## 5. 「这台车现在有没有人在看着」：三层答案，可信度递减

| 问谁 | 可信度 | 为什么 |
| --- | --- | --- |
| **被观察机器上的探针足迹** | 权威 | 它是那件事本身 |
| 控制端的 `observations/` | 可能过期 | 上一个会话异常终止时，本地记录说「结束了」而机器上探针还在跑（#20 第 6 节） |
| 另一个会话的记忆 | 不存在 | 没有跨会话状态 |

所以这个问题**必须去机器上问**，读本地记录得到的「没人在看着」是一个会骗人的绿。

两个坑各自的权威源：

- **残留探针**：#20 定了控制端异常终止时探针留在机器上跑到自己的总时长上限、自杀、留下
  `probe-exit.json`；下一次 `lab watch start` 发现残留探针先回捞。**检出机制已经存在**，就是 #31
  足迹对账里「机器上有、没人声明」那一格（`footprintUndeclared`）—— 本票不新造机制，只是换一个
  提问角度用它。
- **Grant 的剩余额度**：#15 定了 Grant 随探针走、探针带着它离线判定，到期看两个钟（墙上的与单调的，
  先到者算）。**所以「我手上还有多少额度、还剩多久」的权威答案在探针身上，不在控制端。**
  `tier: production` 上 `physical` 的 TTL ≤ 15 分钟不可覆盖，一段跨会话接手的 watch 极可能额度已空。

**一台机器不可达时，那台机器的答案是 `unknown` 而不是「没人在看着」**（#21 定了 `unknown` 与
`notApplicable` 必须分开）。**只要有一台是 `unknown`，整条命令的结论就不允许被读成「没人在看着」。**

## 6. `lab watch status --all-machines`：要有

形状定于 #33（`status` 的一个开关，不是新子命令）；**要不要有归本票，答案是要有。**

判据是 #29 的「这段代码坏掉的时候会不会不出声」，而不出声的那条路径是这一条：

> 上一个会话的控制端异常终止 → 探针留在 `agv01` 上继续跑，带着还没到期的 Grant → 新会话读本地
> `observations/`，看到那段 watch「已结束」 → 它起一次 `lab run` 绑定 `agv01`，run 会起停角色 →
> 探针判定不变量违反 → 触发 Repair 把进程拉回去 → **run 失败，现场被改，而 agent 会去查被测系统。**

这条路径上没有任何一处会红着告诉 agent 真凶是一个上一个会话留下的探针。`lab watch start` 那条路
被 #20 兜住了（它会先回捞残留探针），**`lab run` 这条路没有**。

缺省行为：**去机器上读，不读本地记录**。理由与 #22 那条同源 —— 一次报了成功却没有生效的修复比一次
干脆失败的更危险，而一条报了「没人在看着」而其实有人的 status 比没有这条命令更危险。

`tier: production` 的机器**包含在内，不需要点名**。#5 那条「生产机器必须在 run 里点名」拦的是把角色
缺省绑上去，而这条命令纯只读、不绑定、不执行动词；`lab machine check` 对 production 机器做只读实测
已经是既有做法。输出里标出每台机器的 tier。

## 7. 给 agent 读的文档里，一个数只有三种合法形态

沿用 #24 的「不腐烂」三条，这里是它在文档上的用法：

1. **带筛法**：写下这个数的同时写下怎么重新数出来（一条能跑的命令）。
2. **带守卫**：两份读回来比对，对不上就失败（读不回来也算失败）。
3. **换成规则**：不写数，写怎么现场得到它。

**三种都做不到的，那个数不该出现在文档里。**

还有第四种形态，它必须被点名排掉：**看起来像自己数的、其实是当时凭印象写的**。它在文本上与第 1 种
完全无法区分。本仓的实例是 `CLAUDE.md:18` 的「`CONTEXT.md` has been rewritten **twelve** times」——
`git log -S` 查出那句写于 `dc92b34`（2026-09-08 16:46），**写下它的那一刻真值已经是 14**，今天是 18。
它不是腐烂，是落地时就错了。本票按第 3 种处置它：改成不带数的说法。

**`docs/spec/README.md` 的分片表按第 2 种加守卫**：`lab help --json` 的 `docs` 字段现场派生
`docs/spec/*.md` 的清单（文件名 + 一级标题 + 头行 `<!-- 来源：#N -->` 的票号），与 README 的分片表
比对，对不上即失败。这是 2026-09-09 那次漏行的根治办法 —— 当时 `96-ci.md` 已落地而分片表只有 16 行，
字符串 `96` 在整份 README 里出现 0 次。

## 8. 起 watch 的三条硬约束：文档写「为什么」与「什么时候」，参数由 help 派生

- **`--courier <文件路径>` 或显式 `--no-courier`，二者缺一拒绝启动**（#28）。理由要一起写：#20 定了
  那十类事件是「必须让人知道的」，缺省静默不送会把那条定义架空，而**失败的方式是不出声的** ——
  watch 照跑、账照记、人什么都收不到。凭据给路径不给 URL（URL 会进进程列表与 shell 历史）；
  `--no-courier` 是给自测与 CI 的，不是给生产 watch 的；`lab watch courier-check` **会真的往群里发
  一条消息**，不是干跑。
- **绑定里有 `tier: production` 机器时必须给 `--vigil <文件>`，且没有 `--no-vigil` 逃生口**（#30）。
  一句话记住它：**动生产机器的 watch 要两份配置文件，不是一份。** 另三条是判断不是参数：watch 不是
  无人值守的（RC 第 11 节：真车动作逐次授权加现场物理安全 GO，每次都要、不可复用）；没收到摘要不
  代表一切正常（#28 空摘要不发），**没收到 Vigil 的日报**才是「有东西不对而且没人知道」；Vigil 说的
  是「我听不到控制端」而不是「控制端挂了」。
- **`lab machine sweep` 缺省 `--dry-run`**（#31）。agent 不需要记得跑清理，但需要知道**自己不能删
  什么**：`HALT` 哨兵、`evidence/` 与 `observations/`、被测系统的东西。第三样要删得走 `lab do` 的
  适配层动词并按 #15 的 `physical` 判 —— **agent 无法无人值守地做这件事，这是设计不是缺陷。**

另有一条通用判据，写任何「让某样东西不存在」的动作前都要问：**做没做成会不会不出声**（#31）。

## 9. `docs/agent-notes.md`：这张图踩过的坑

**它不是规格、不是词汇、不是操作手册**，是「已经付过钱的调研」：哪些数会过期、筛法有哪几种错法、
先例通常藏在哪、哪些问题已经被别的票答过。今天这些东西只活在系统临时目录的开工 prompt 里
（2026-09-09 实测：九个文件 260428 B，其中八份 216697 B 是上一批会话留下的），**随会话消失，一个字
都不持久**。

按 #13 的判据「不是代码的东西现在就落，除非它落地之后会自己动起来」—— 一份 Markdown 落进去不会自己
动起来，所以**现在就落**。

它分两节，因为两节的寿命不同：

- **A. 与这张图绑定的**：怎么解一张 wayfinder 票、先例位置清单、哪些票已经定了什么。**图走完即冻结**，
  不删（它是这张图为什么长成这样的记录）。
- **B. 与图无关的**：数会过期、筛法会错、引来的数、核变动。**对任何会话都成立**，图走完之后仍然是它
  的主体。

**写入时机不是收尾清单上的第六件事**，理由是收尾那五件事各有可核的产物（决议评论、票的状态、地图那行、
规格文件、雾），而「把坑写进去」没有真值可以对账，放进那张清单等于放进一件坏了不出声的事。它按**事件**
触发：

> 当你发现自己正在犯的错，是另一张票也犯过的错 —— 那一刻就写。

**它去重，不堆砌。** 那六条教训今天在五份 prompt 里各抄了一遍，正是 #24 「一个地方 + 两个调用点」
要消除的形状。每张票自己的调研留在票里，不往这里抄。

## 10. 不加新词条

`docs/agent-notes.md` 记的是解题过程不是 lab 的运行时概念，而 `CONTEXT.md` 的边界是内核层的词
（今天 39 个词条，筛法 `grep -cE '^\*\*[A-Za-z][A-Za-z ]*\*\*:' CONTEXT.md`）。撞名检查
（2026-09-09，两个口径都跑）：`Briefing` / `Logbook` / `Playbook` / `Primer` / `Handbook` /
`Notebook` 在 lab 仓与三个被测仓精确口径全部 0 命中 —— **没有一个已经在用却没进词汇表的词**，
也没有一个需要立的新词。

## 11. 与相邻票的边界

- **不定各章写什么**（#16 定的收尾第五件事），**不定接入文档骨架**（#4 已定六节），**不定命令与参数
  长什么样**（#33 已定，且它们不落盘）。
- **证据与 Observation 的检索、保留**归 #25 与 #26，本票只说「有没有人在看着」，不说「看到的东西存哪」。
- **给人的入口**归 #27；地图 Out of scope 定死不做给人用的交互界面。本票的读者只有 agent ——
  CI 是 lab 的第二类调用方但它不是 agent（#13），它不读文档，读的是退出码表。
- **「一条场景的正确结局就是红，怎么表达」仍在雾里**（归 #21 或 #10 的后续），所以本票**不写**
  「一个新会话看到红该怎么理解」—— 那条依赖一个还不存在的机制。
