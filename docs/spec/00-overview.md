# 总览

## 1. 这是什么

一个 agent 优先的多机工具：**通用内核加适配层**，对同一套被测系统提供两种模式。

- **Run** —— 跑场景、判红绿、产出 Evidence。有终点。
- **Watch** —— 持续观察生产运行、检测不变量违反、执行修复、产出 Observation。没有终点。

两种模式**共享** registry、adapter、role、transport、控制面读原语、日志回捞与关联；
**不共享** scenario、断言的时点语义、rig 的启停、桌面独占。

第一个适配层是 WIRE_TO_GATE MVP，它的三个被测进程住在 `8005-agv-control-server`、
`8005-agv-onboard-hmi` 与 `slots-simulator`。

## 2. 完成标准

三条都要：

1. 今天 `8005-agv-control-server/scripts/l2/` 的六条场景由 lab 一条命令在两台以上远程客户机
   （含真车）上跑完并产出证据；agent 只靠 lab 的 CLI 就能复现、修、验证。
2. 去掉模拟器、接真 IO 模块与真仓位的生产装置下，lab 持续观察一台在跑实际任务的车，Observation
   能还原一次完整旅程的跨机器消息链；检测规则集在 `evidence/l2/` 的历史红证据上回放能命中已知故障。
3. 至少一个修复动作走通完整链路——检测、安全门判定、执行、人可读的账——机制在 lab tier 上验证，
   生产装置上的差异只有安全门的判定结果。

## 3. 不再重开的边界

- **产物是规格不是代码**（本目录就是那份规格）。
- 通用内核加适配层，**接入文档是一等产物**，别的系统靠它嵌入。
- **用户只有 agent**；CLI 输出 JSON，子命令名人可读但不为人设计。
- L2 迁移进 lab，`8005-agv-control-server` 只留 L1。
- **不改被测系统代码**——被测系统今天的样子就是约束。三仓的配合改动另起一张图。
- 实现是 **pwsh 7 内核**，UI 驱动用 `winapp ui` v0.6.0，**不写 `lab-ui`**，**整个仓库没有 .NET 工程**。
- **Watch 与 Run 并列**，不泛化 Run、不做成一串短 Run。Observation 与 Evidence 并列而非其子类。
- **修复是全权的**：agent 可做任何修复动作，靠安全门拦，不靠白名单。
- **Watch 检测到异常只能拉起「只读诊断」场景**，理由是证据可信而非安全——完整 Run 会破坏它正在
  诊断的现场。
- **Watch 不做配置改写**，不扰动生产。
- **Watch 的编排跑在控制端**，检测下推到被观察机器上的探针。
- **不变量与断言共用判据模块**，区别只是时间语义。
- **人可读的账是 Observation 的一部分，不是界面**——一个能自己动手改生产系统的 agent 必须留下不
  需要 agent 就能读懂的流水。

## 4. 不在范围内

- 三仓的配合改动（`AutomationId`、统一日志格式与 `runId` 注入、自动化平面扩展）。
- MCP server —— v1 的 agent 直接调 CLI。
- **给人用的交互界面**。但这不含「人可读的账」。
- **真实硬件的资格认定**。界线是：在真硬件上观察它、跑场景、检测异常，都在范围内；认定这套硬件
  合格，不在。
- GitHub 托管 runner。

## 5. 词汇

仓库根 `CONTEXT.md`。「Agent」只指 AI 一方，内核说 machine 与 role，vehicle / slot / barcode 这类
词属于适配层。
