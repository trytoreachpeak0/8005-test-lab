# 这张图踩过的坑

**这不是规格、不是词汇表、也不是操作手册。**它是已经付过钱的调研：哪些数会过期、筛法有哪几种错法、
先例通常藏在哪、哪一类问题已经被别的票答过。规格在 `docs/spec/`，词在 `CONTEXT.md`，命令敲
`lab help --json`。

**开工前读一遍**，不是遇到问题时才读。

**什么时候往里写**：当你发现自己正在犯的错，是另一张票也犯过的错 —— 那一刻就写。它不在收尾清单上
（收尾那五件事各有可核的产物，而这一件没有真值可以对账），所以它靠这个事件触发，不靠记性。

**写的时候去重，不堆砌。**每张票自己的调研留在票里；只有「第二次犯」的才进来。已经在别处的东西
一律只留指针：已关闭的票定了什么在**地图的 Decisions so far**，词的定义在 `CONTEXT.md`，
命令与参数在 `lab help --json`。

A 节与这张图绑定，图走完即冻结但不删；B 节与图无关，对任何会话都成立。

## A. 与这张图绑定的

### A1. 开工三十秒，别跳过

1. `gh issue view <票号> --json state` —— 确认票还开着。
2. `git -C repos/8005-test-lab log --oneline -5` —— 看有没有别的会话正在解它。
3. `git status` —— 工作树脏不脏。

**这张图是多个会话并行推进的，一张开着的票不等于没人在解。**解 #31 的那个会话跳过了这一步，
做完一整轮调研与实测才发现票在它开工后 44 分钟就被另一个会话解完关掉了，而且它用 Write 覆盖了对方
已提交的规格文件。

推论：**Write 一个「新」文件前先 `git status`** —— 输出里是 `M` 而不是 `??` 就是警报。

### A2. 先例藏在哪，按找到的次数排

1. **本图已关闭的票**（地图 Decisions so far 是索引）。

   脚本，而没有人写下那句「所以它的归宿就是 Watch + Probe + Repair」。
3. **`docs/spec/`** —— 十七份，索引是它的 `README.md`。
4. **被测系统的源码**。#28 与 #30 两票的三段答案骨架全在被测系统里，而票的正文一个字都没提它们存在。
5. **`remote-ops/` 与名字跟本题毫无关系的脚本**。#22 的「只读诊断」整条答案躺在
   `remote-ops/status/Get-WireToGateStatus.ps1` 里；#17 的 `stop` 钩子完成判据整段在

6. **机器自己**（#31：一条能在本机 30 秒跑完的命令）。

**先例是活的。**每次花 90 秒核它们是否触及你引用的事实：#21 解到一半发现三个 commit 是当天上午刚推
的；#28 解到一半被测仓在 20:02–20:13 推了三个提交与两个 PR 合并；#24 解票期间控制端又推了四个，
而**第四个正是本票在找的那个答案的完整实现**。解票期间收到文件变动通知就去读，别当噪音。

### A3. 票的前提会过期，而改掉它的东西可能在这张图之外

#13 四条正文里三条的前提变了，**其中两条是被 lab 这张图之外的东西改的** —— 一条被工作区根
`CLAUDE.md` 推翻，一条被 `8005-agv-program` 那张图的票整条答完（连实现带三层验收）。

所以逐条对着正文的每一个问号答之前，搜索面至少要包括：

- `gh issue view <每张相关的已关闭票> --comments`，搜那个脚本名 / 字段名 / 概念名；
- `git log --since=<票创建日> -- <相关路径>`，本图之外的仓也搜；
- 工作区根 `CLAUDE.md` 的 git log；
- `8005-agv-program` 的 `docs/adr/` 与 `.scratch/`，以及 `8005-fp/` 那几个 worktree 分支。

**最贵的一种是：票正文里的问题清单会过期。**#24 的一个问号在票开着的期间已被另一张票整段答完，
差点重答一遍。它比「引来的数会过期」更难发现，**因为一个问号看起来永远像是还没被回答**。

### A4. 收尾是五件事，别只做前两件

决议评论 → 关票 → 更新地图 Decisions so far → 更新 `docs/spec/` 的对应文件 → graduate 该毕业的雾
（判据是「现在能不能把问题说清」，不是「现在能不能答」）。

四条子项：

- **新建一份规格文件时，`docs/spec/README.md` 的分片表要跟着加一行。**（2026-09-09 漏过一次：
  `96-ci.md` 落地了而分片表没有它。）
- 顺带检查这张票的结论有没有让某张已关闭的票需要补修正评论 —— 历史上每张票都补出十几条。
- **地图里的数字最容易失真，而且有时就是你自己刚弄假的。**多张票在加自己那行的同时改掉了两三处别人的。
- **关票前把决议从头读一遍，找的是你自己刚写下、却没按本票标准验过的句子。**这一步找的不是「错的
  句子」，是「没验过的句子」—— 验完对的那些，你写它的时候和写错的那些是同一个状态。

规格提交后要 push：留在本地未推等于下一个会话读不到。

### A5. grilling：先切，切到没得切为止

**只把范围、代价、风险交给用户**（「会不会多花一倍工时」「出了事谁承担」「这条要不要划出
destination」）。字段名、enum 值、动词名、目录层级、默认数值、文件放哪，这类自己定完写进决议的
「自己定的细节」一节。

**投问题之前，对每一个候选问一次「有没有一条已定的判据能把它切了」，做完一遍之后，把剩下的每一个
再问一次，直到一轮下来一个都切不掉。**写成一个待办，别指望记得 —— #13 读过这条纪律仍然漏掉了它，
剩下的三个问题里有两个能被已定判据切掉。

**用户说「你推荐哪个」时不是在放弃判断，多半是选项列表漏了正确答案**，而漏的方式往往是同一种：
把问题构造成了一条线性档次或一个二选一，**而正确答案在另一个维度上**。#33 六个问题四个构造成
「用多大力气守这条规则」，而正确答案是「这段代码坏掉的时候会不会不出声」。#34 四个全被交回，四个
的正确答案都在给出的档次之外。

**一个已知不成立的选项不该占一格**（#24）。**正文里那种「顺带一提」的前提最该核**，因为它不是票要
答的问题，所以从来没人验过它。

**用户改主意时去找那个改法背后的原则**，把原则写进决议，否则下一张票会照旧定位重开它。

## B. 与图无关的

### B1. 一个数的三种来源，而第三种最危险

「自己数的」「引来的」之外还有第三种：**看起来像自己数的、其实是当时凭印象写的**。第三种在文本上
与第一种完全无法区分。

实例：lab 的 `CLAUDE.md` 写着「`CONTEXT.md` has been rewritten **twelve** times」。`git log -S` 查出
那句写于 2026-09-08 16:46，**写下它的那一刻真值已经是 14**，2026-09-09 是 18。它不是腐烂，是落地时
就错了两次。

**写下一个数时同时写下：它是什么时候的、会不会长、你是怎么筛出来的。**会长的换成规则，快照另存。
一个数只有三种合法形态 —— 带筛法、带守卫（两份读回来比对，读不回来也算失败）、或者干脆换成规则。
三种都做不到的，那个数不该写。

**引来的数会跟着来源一起错**，而且有一种特别隐蔽：**从一个你自己刚刚判定有错的句子里，引它的另一半。**
#13 判定了「现在是四条，合计约两分钟」里的「四条」是错的（实际 8 条），然后在另一节引用了同一句话里
的「约两分钟」—— 实读三次 run 是 6 分 02 / 7 分 03 / 10 分 28 秒。它比别的都隐蔽，**因为它数的是耗时，
没有真值可以 `ls` 出来**。

### B2. 筛法的十三种错法，每次都不一样

1. 大小写：`grep -ioE` 把小写也算进去了。
2. `wc -l` 数的是**行**不是**命中次数**（一行里出现两次就少数一次）。用 `grep -o | wc -l` 数命中，
   `grep -n | wc -l` 数行。
3. 命令**静默失败返回空**，`wc -l` 得 0，于是十八个候选词全报 CLEAN。**先用一个已知存在的词校准筛法。**
4. **用错的键去对账**，跑出「全部命中」。
5. **压根没跑筛法** —— 那个数是从一张已关闭的票的决议里引来的。
6. `head -N` 让不完整的列表看起来像全集（20 处其实 24 处）。
7. `grep -rhE ... | grep -v Migrations`：`-h` 抑制了文件名，所以路径过滤**静默失效**。正确写法是
   `--exclude-dir=`。
8. **用行首锚点去数可能出现在行内的东西**：`^\s*exit [0-9]` 得 0，而 `exit 1` 就写在
   `if (...) { exit 1 }` 里。
9. **范围表达式被空行提前截断**：`sed -n '/^## 分片/,/^$/p'` 只取到标题后的那个空行，表格一行都没进去。
10. 数的是**耗时**这类没有真值可 `ls` 的东西（见 B1）。
11. 从自己刚判定有错的句子里引另一半（见 B1）。
12. 凭印象写下的数（见 B1）。
13. 一个数在两个口径之间取了中间值：scratchpad 目录「232 KB / 八个文件」，实测是
    216697 B / 8 个（不含当天新写的那份）或 260428 B / 9 个。**两个口径都对，中间那个数哪个都不是。**

**规则：两个口径都跑，且先用已知词校准。**撞名检查的标准形式是
`grep -rhoE --exclude-dir=.git --exclude-dir=bin --exclude-dir=obj -e "\bWord\b"` 与
`grep -rhoiE ... -e "word"`，**两个都是 0 才算干净**。

### B3. 引用另一个仓的 issue，读到最后一条评论再下结论

并核对 PR 是不是真的合并了。#9 曾据一份 51 分钟前就已自我更正的报告下结论；#16 第六次复核时才翻牌：
那个 PR 用的是 merge commit 不是 squash，所以旧 commit 仍可达。每次花 30 秒 `gh pr view`，它已经救过
两次。

同形的还有：**一段逻辑是什么时候落地的，决定了你能拿它统计多少历史**（#31 用 `git log -L` 把口径从
80 次收窄到 77 次）。

**怀疑另一张票给错了理由时去核，核完可能发现错的是自己** —— 但去核的动作仍然是对的，#17 那次核对
翻出了另一个真问题。

### B4. 实测：只读探一次是合法的，而且经常改结论

#12 探三台机器改了两条结论，#23 探出三条每条都改结论，#30 一次改了四条，#31 一次改了五条。

- 探远程前先 `Find-NetRoute -RemoteIPAddress <目标>` 确认没走 Clash TUN（已核：agv01 与 factory01 走
  ifIndex 19 Wi-Fi、vm01 走 ifIndex 15 vEthernet，Clash 是 43）。
- **只有拿到了对端产生的字节才算测到了对端。**`vm01` 的机器级 `HTTPS_PROXY` 指着控制端的 Clash，
  所以从 vm01 发出的连通性测试必须带 `-NoProxy` 重测。判定连通看**读回的 body**，不是状态码。
- **实测的代价要算，算完可以决定不做，但理由要写进决议**（#17）。#24 是「一次远程都没探而材料仍然
  最硬」的一次，全部落在读代码、读注释块与 `git log` 上。
- **注释块写的是意图，代码写的是拓扑**；要意图读注释，要拓扑读代码。
- **「不要提前猜」不等于「不能现在测」。**一段代码旁边写着「到那时再加，不要提前猜 ACL 该长什么样」，
  而 #13 在本机建了一个命名内核互斥体、读回默认 DACL，一次调用就定死了答案。那句话拦的是猜。

### B5. 说重了要更正，说偏了更贵

**你在提问时可能把风险或代价说重了，发现了就在决议里更正**，别让那个夸大的版本留在记录里。
#16 把桌面互斥体测试说成对被测系统的风险 —— 被测系统不认识那个互斥体。

**比说重了更贵的是说偏了**：#13 在选项里写「网络上够得着，缺的只是一把 ssh key」，那句把一个**治理**
问题描述成了纯技术问题，掩盖了一条已定的判据，让用户以为那是一个成本取舍。**说重了会让用户多犹豫
一次；说偏了会让用户在一个错的维度上做决定。**

**更正的对象不一定是自己的提问，也可能是票的正文**（#30）—— 正文的前提出错比自己说重了更常见，
也更贵。
